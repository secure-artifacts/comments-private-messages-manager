使用方式：先在 Facebook 中切换到你要管理的公共主页身份，然后启动任务。插件会固定打开 1 个 https://www.facebook.com/professional_dashboard/comments_manager 工作标签页，并在该页面内从新到旧串行处理评论。

⚡ 反向关键词（不触发）与私信话术

默认所有评论都发私信。如果评论包含或等于这里的反向关键词，则不发送。所有规则中的私信话术会合并随机使用。

🛡️ 评论优先级、冷却与重试

这些设置决定扫描速度、用户冷却、旧评论回溯以及发送失败后的处理方式。

单工作页逻辑：启动后自动切到“所有评论”。固定 1 个工作标签页严格串行：按时间定位评论 → 弹出 Messenger 私信框 → 发送并确认 → 记录去重 → 继续下一条。后台按你设置的刷新分钟数刷新一次，再从顶部重新检测最新评论。只处理最近7天；失败达到设定次数后跳过。
秒
备注：点击评论行“发消息”后，插件会在这段时间内等待“通过 Messenger 回复 / 发消息给…”私信框真正出现；如果第一次没有出现，会重新定位按钮再尝试，避免 Facebook 加载慢被误判为失败。
秒
备注：只有真正点击私信框里的发送按钮后才开始计时。期间检测弹框关闭、输入框清空、已发送提示和明确失败提示；检测到“正在发送”时还会额外等待。
备注：解决“消息实际已经发出，但 Facebook 没有提供明确成功状态”时插件反复重试的问题。只有出现“发送失败 / 无法发送 / 重试”等明确错误才判定失败。
秒
备注：有新评论时 MutationObserver 会提前唤醒；这个值主要用于页面没有变化时的补扫。它只扫描当前页面 DOM，不会刷新整个 Facebook 页面。
秒
备注：私信确认成功并记录去重后等待这段时间，然后直接继续扫描下一条评论；这里不会刷新页面。数值越大，连续发送速度越慢。
分钟
备注：可以手动设置 2、3、5 分钟等。刷新只由后台定时器触发；发送成功、发送失败、空闲扫描、切换筛选都不会额外刷新页面。
备注：开启后仅由后台定时器按上面的分钟数刷新工作页；关闭后页面不会被插件主动定时刷新。
小时
备注：同一个用户即使在不同贴文、视频或 Reel 下重复留言，也会在这段时间内跳过第二次私信。设为 0 可关闭用户冷却；“清空用户冷却”会让历史用户重新具备发送资格。
次
备注：同一条评论连续发送失败达到此次数后，会记录为失败并跳过，避免一个异常用户一直卡住整个流程。
秒
备注：建议 2–5 秒。单次失败后等待这段时间再重试；达到最大重试次数后会记录失败并跳过，再继续下一条。
天
备注：默认最近 7 天。超过这个时间范围的评论不会再发送；列表按时间从新到旧处理，避免无限回溯非常久以前的留言。
备注：开启后顶部没有新任务时会继续向下滚动；关闭后只处理当前顶部可见的新评论。
备注：建议开启。若 Facebook 内部跳转导致离开评论管理工具，插件会提示并恢复到正确入口；不会高频刷新。
固定规则：每次页面加载自动选择“所有评论”；默认所有评论都发私信；只处理最近7天；发送成功后绝不刷新，直接继续下一条；只有后台按你设置的分钟周期允许刷新；命中「反向关键词」或处于用户冷却期才跳过。
备注：检测到验证码、临时限制或安全检查时立即停止任务，避免继续操作。

💾 配置导入与完整备份

完整备份不仅包含设置、反向关键词和私信话术，还包含“评论处理与私信日志”、已处理评论去重记录、用户冷却历史与失败记录。更换浏览器后导入，可避免已联系用户再次被私信。

完整备份导出

备注：导出 JSON 会同时保存设置、规则、日志、用户冷却、已处理评论及处理元数据。运行中的标签页和临时任务锁不会被备份。

完整恢复 / 导入

备注：导入新版完整备份会恢复历史去重与日志；旧版仅含设置/规则的配置文件仍可导入，但无法恢复当时未备份的历史记录。导入后任务保持停止。

重要：备份包含评论、用户名和主页链接。请勿分享给他人。换浏览器时请导出完整备份，不要只导出 CSV 日志。
